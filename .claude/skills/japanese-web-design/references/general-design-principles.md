# 一般的なデザイン原則（業種を問わない普遍パート）

`principles.md` が日本語特有の文字組み・縦組・AIっぽさ回避を扱うのに対し、このファイルは**言語を問わない一般的なレイアウト・タイポグラフィ・進め方の原則**をまとめたもの。新規にページ全体をレイアウトするとき、または実装後の最終レビュー（`SKILL.md` ステップ7）のときに参照する。常に読み込む必要はない。

## 1. レイアウトの4原則（近接・整列・強弱・反復）

- **近接（Proximity）**：関連する要素は近づけ、無関係な要素とは間隔を空ける。余白そのものが情報のグルーピングになる。
- **整列（Alignment）**：要素は見えない基準線（グリッド）に沿って配置する。左揃えが最も読みやすく、しっかりした印象を与える。中央揃えは短いコピーやフォーマルな場面に限定的に使う。
- **強弱（階層／コントラスト）**：重要な情報ほど大きく・濃く・コントラスト高くし、視線誘導を作る。テキストと背景のコントラストは可読性に直結する（WCAG AA基準を下回らない）。
- **反復**：色・フォント・余白の単位・角丸の半径などを繰り返し使うことで、サイト全体の一貫性と「システムとしてのデザイン」感が生まれる。

## 2. 配色の目安比率

70:25:5 の比率（ベースカラー：メインカラー：アクセントカラー）を出発点にする。

- **70%**：背景・余白など、ページの大部分を占めるベースカラー
- **25%**：ブランドカラー・見出し等のメインカラー
- **5%**：CTAボタンなど、行動を促すアクセントカラー

この比率はあくまで出発点であり、業種データ（`data/industry_tone_moderate.csv` 等）の実測トーン分布と矛盾する場合はデータを優先する。

## 3. タイポグラフィの基本

- サイト全体で使うフォントファミリーは2〜3種類以内に絞る（見出し・本文・ラベル程度の役割分担）。
- 本文の1行の長さは、欧文でおよそ80文字以内、日本語ではそれよりやや短め（目安45〜65字程度）に収める。長すぎる行は視線の移動距離が長くなり読みにくい。
- 行間は本文サイズの1.5〜2倍程度が目安（日本語は欧文より広めが基本。詳細は `principles.md` の「字間・行間」参照）。
- セリフ体（明朝体）はサンセリフ体（ゴシック体）よりもやや広い行間を必要とする傾向がある。
- 見出しで単語やフレーズを一つだけイタリック・太字・別色で強調する、意味なくALL CAPSのラベルを付ける、といった「とりあえずそれっぽくする」処理は、ブリーフが求めていない限り避ける。

## 4. モーションは節度をもって

- ページ全体で「見せ場」となる演出は1箇所（ページロード時の一連の動き、または一つの注目すべきリビール）に絞る。すべてのセクションに fade-and-slide-up を、すべてのカードに hover トランジションを付けるのは「選択」ではなく「デフォルト」である。
- ユーザーの操作（開く・展開する・確定する）に応じたモーションは、何が変化したかを示すので歓迎される。
- `prefers-reduced-motion` を必ず尊重する。

## 5. UIライティングの原則

- 言葉は理解を助けるために存在し、装飾のためではない。
- システムの内部用語ではなく、ユーザーの平易な言葉で名付ける。凝った表現より具体的で読みやすい表現を優先する。
- 能動態を使う。CTAボタンは実際に起きることをそのまま書く（「送信する」ではなく「見積もりを送る」等）。フローの中でアクション名を一貫させる（ボタン「公開する」→トースト「公開しました」）。
- エラー・空状態のメッセージは方向性を示す：何が起きたか・どう直すかを説明する。謝るだけ、曖昧なだけのメッセージにしない。

## 6. 進め方：計画 → レビュー → 実装 → 批評

新規にページやセクションをデザインするときは、以下の4段階を踏む。

1. **計画（トークン化）**：配色（4〜6色の主要な色をhexで）・タイポグラフィ（フォントとその役割）・レイアウト（一文の説明＋簡単なワイヤーフレーム、整列方向を明記）・このデザインを"らしく"する原則、を先に言語化する。
2. **実装前レビュー**：上記の計画を業種データ・ブリーフと照らし合わせ、「陥りやすいAI丸わかりパターン」（`principles.md` 参照）に当てはまっていないか確認する。当てはまっていれば、何をどう変えたかを明示してから実装に進む。
3. **実装**：レスポンシブ対応、キーボードフォーカスの可視化、`prefers-reduced-motion`の尊重、アクセシブルなコントラスト、調和の取れた配色という「品質の下限」を満たしながら実装する。CSSの詳細度が高すぎてセクション単位のpadding/marginが打ち消し合っていないかにも注意する。
4. **批評（最終確認）**：スクリーンショットを撮って実際に見て確認する。以下を必ずチェックする。
   - 見出し・リード文で行末の孤立文字（泣き別れ）が起きていないか（`principles.md` の該当セクション参照）
   - モバイル幅（375px前後）でレイアウトが崩れていないか
   - コントラスト比がWCAG AAを満たしているか
   - 「大胆さを効かせる場所」が1箇所に絞られており、それ以外は静かに保たれているか。最後に、ブリーフに貢献していない装飾を一つ削れないか検討する（引き算の仕上げ）。
