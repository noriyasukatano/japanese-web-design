# 日本語Webデザインの原則（散文型パート）

このファイルは、SKILL.mdから「詳しく読む必要があるとき」だけ読み込まれる参照ファイルです。数値データ（`data/`以下のCSV）が「業種ごとに実際どうなっているか」を教えてくれるのに対し、ここでは「なぜそうすべきか」という判断基準・原則を扱います。

## 1. 日本語の文字組は欧文前提のデザイン原則では抜け落ちる

多くの汎用デザインSkill・デザインシステムは欧文（特に英語）を前提に作られており、日本語特有の文字組みルールが抜けています。日本語サイトを作るときは、以下を必ずチェックしてください。

### 禁則処理（きんそくしょり）
行頭に「、」「。」「」」「』」「ー」などの句読点・閉じ括弧を置かない、行末に「「」「『」などの開き括弧を置かない。CSSでは `word-break: normal;` と `overflow-wrap: break-word;` の組み合わせ、または `line-break: strict;` を明示する。長体・約物の位置がずれるレイアウトは避ける。

### 約物（やくもの）のアキ
句読点・括弧・記号の前後に不要な半角スペースが入っていないか確認する。全角の句読点の後に半角スペースを入れる、逆に約物同士が詰まりすぎている、といった処理ミスは素人っぽさに直結する。`font-feature-settings: "palt"` (プロポーショナルメトリクス) を使うと、約物の間隔を自然に詰められる場合がある。

### 和欧混植（わおうこんしょく）
日本語の本文中に英数字が混じる場合、和文フォントの数字・アルファベットをそのまま使うと不格好になりやすい。欧文専用フォント（例: `Helvetica Neue`, `Inter`）を数字・英字だけに当てる「和欧混植」を検討する。`font-family: "游ゴシック", "Inter", sans-serif;` のようにfont-family宣言の順序で緩やかに制御することもできるが、厳密にやるなら `<span lang="en">` で英数字部分を囲みフォントを分ける。

### 字間・行間
日本語は欧文よりも行間を広めに取らないと窮屈に見える（目安: `line-height: 1.7〜2.0` 程度、欧文の1.4〜1.6よりも広い）。見出しなど大きい文字サイズでは `letter-spacing` をわずかに広げる（0.02em〜0.05em程度）と、和文特有の詰まった印象を緩和できる。

### 明朝体 / ゴシック体の使い分け
ゴシック体＝現代的・親しみやすい・可読性重視。明朝体＝伝統・格式・高級感・和の情緒。今回集計したデータでも、ウェディング業種（特に神社・和装系）で明朝体系フォントの使用率が高いことが実測で確認できている（`data/css_reference_examples.csv` 参照）。業種のトーンと矛盾するフォント選定（例: 神社サイトに丸ゴシック）は避ける。

### 全角 / 半角
数字は原則半角、記号（！？）は文脈で統一する（全角と半角が混在しない）。単位・URLなど機械的な文字列は半角に統一。

### 行末の孤立文字（泣き別れ）を防ぐ
禁則処理（行頭に句読点を置かない等）とは別の問題として、見出しやリード文で**単語・文の最後の1〜数文字だけが次の行に送られる「泣き別れ」**がある。読みにくいだけでなく、素人っぽさが最も出やすい箇所の一つなので、デザイン適用後の最終確認で必ずチェックする（`SKILL.md` のステップ7参照）。

対処法は優先順位順に以下の通り。

1. **`text-wrap: pretty;`（本文・リード文向け）** — 段落の最終行に単語が1つだけ残る「オーファン」を自動的に回避する。Chrome/Edge 117以降、Safari 26以降で対応（2026年9月時点でグローバル対応率 約87%）。Firefoxは未対応なので、崩れても致命的でない箇所に使う前提で採用する。
2. **`text-wrap: balance;`（見出し・短いキャッチコピー向け）** — 複数行の見出しを行の長さが均等になるよう自動調整する。Chrome 130／Safari 17.5／Firefox 121以降で対応（グローバル対応率 約93%、`text-wrap: pretty`より対応が広い）。1〜3行程度の短い見出しに向く。既に `SectionHeading` 等で明朝の見出しに使っている実装例がある場合はそれを踏襲する。
3. **フォールバックとして手動`<br>`を意味の区切りに挿入** — 上記CSSが使えない・効かない場合、または特定の改行位置を確実に固定したい場合は、単語や文節の切れ目（句点・接続詞の前など）に手動で `<br>` を入れる。行末に1〜2文字だけ残る禁物な改行位置を目視で確認し、直前の意味の区切りまで戻す。
4. **文字サイズ・字間・コンテナ幅の微調整** — レイアウト上どうしても直せない場合、その要素だけ `font-size` をわずかに下げる、`letter-spacing` をわずかに詰める（-0.01〜-0.02em程度）、またはコンテナの `max-width` を微調整して、問題の行に文字が収まるようにする。これは最終手段であり、デザインシステム全体のスケールを崩さない範囲でのみ行う。
5. どうしても解決しない場合はコピー自体を1〜2文字削る・言い換えることも検討する（文言の変更はユーザー確認を取ってから）。

### 縦書きの要否
和風・伝統的な業種に限らず、短い日本語コピーがある箇所では縦組（`writing-mode: vertical-rl;`）を積極的に検討する。詳しい判断基準・実測データは「2. 縦組（縦書き）という選択肢」を参照。

## 2. 縦組（縦書き）という選択肢

このSkillを作るきっかけになったのも、この縦組（縦書き）の観察だった。Webでは横組みが圧倒的多数派であるため、縦組を使うだけでそれだけで際立った特徴になる。特に短い日本語コピー（ヒーローのキャッチコピー、見出し1〜2行程度）がある場面では、横組にする前に「これは縦組にできないか」を必ず検討する。

### 縦組がもたらす印象
- 縦組は横組より「和」の情緒・日本らしさを喚起しやすい。短いコピーを縦に置くだけで、サイト全体の印象が上がる場合が多い。
- 明朝体×縦組は「気品」「高級感」「静謐さ」を伝えやすい。
- ゴシック体×縦組は「素直な可愛らしさ」「誠実さ」を、重さを出さずに伝えやすい。
- Web上での使用頻度自体が低いため、縦組はそれだけで「量産型のAIっぽいデザイン」から離れる強い手段になる。

### 実例14サイトの観察（`data/vertical_writing_examples.csv`）
縦組を効果的に使っている14サイトを実測した（`getComputedStyle`で font-family / font-size / letter-spacing / line-height / font-weight を取得。Canvas・WebGL実装の2サイトのみCSS値が取得できず視覚確認）。傾向は大きく3パターンに分かれる。

**パターンA: 明朝体 × 広めの字間・行間 → 気品・高級感（14サイト中7サイト）**
shirahone.org、kajimanomori.co.jp、obirin.ac.jp、unipos.co.jp（太字）、nasu-ougiya.com、kei-inc.jp、shiroyamakumano-jinja.jp。「格式」を狙うサイト（老舗旅館、神社、大学、老舗和菓子店）は letter-spacing を 0.1〜0.23em 程度まで広げ、line-height も 1.5〜2.0em とゆったり取る傾向がある。kajimanomori.co.jp（高級旅館）は文字間 5px（≈0.22em）、obirin.ac.jp（大学）のヒーローコピーは文字間 4.83px（≈0.23em）・行間 1.9em と、いずれも「余白の多さそのもの」が品格の演出になっている。kei-inc.jp（デザインスタジオ）はフォントサイズ自体は 17.8px と控えめだが、行間を 1.7em まで広げ、周囲の余白と合わせてバランスを取っている（本人コメント:「文字組が小さい割にページの余白がきちんと設定されているので、全体のバランスが取れている」）。

例外的に unipos.co.jp（採用サイト）は明朝体でも太字（700）・行間 1.0em（タイト）という組み合わせで、格式よりも力強さ・訴求力を優先している。「明朝＝必ず上品でゆったり」ではなく、weight・line-height の調整次第で明朝でも力強い表現ができる好例。

**パターンB: ゴシック体 × タイトな行間・weight600〜700 → 力強さ・誠実さ（14サイト中5サイト）**
meikei.ac.jp、takachu.co.jp/recruit、ginger.sakatashop.jp、tanica.jp/amazake、syuzgen.com。教育機関の訴求ヒーロー（meikei.ac.jp）や採用サイト（takachu.co.jp/recruit）は weight 700・line-height 1.0〜1.8em 程度で力強さを出している。ginger.sakatashop.jp は「文字間の設定や行間も意図的に狭くすることでフォントの力強さが表現されている」（本人コメント）という明確な意図があり、EC・プロダクト系のような親しみやすさと説得力を両立したい業種と相性が良い。tanica.jp・syuzgen.com は逆に控えめなサイズ・落ち着いた字間で「ちょうど良い」（本人コメント）上品めのゴシック運用の例。

**パターンC: Canvas/WebGL・3D演出による拡張表現（14サイト中2サイト）**
j-cat.co.jp、veryman.jp の2サイトは通常のCSS `writing-mode` ではなく Canvas/WebGL や 3D transform で縦組テキストを演出しており、`getComputedStyle` では値が取得できない。標準CSSの範囲を超えて、縦組を動き・アニメーションと組み合わせるとさらに強い印象を作れるという参考例だが、実装コストは高い。通常の制作では `writing-mode: vertical-rl` ベースの実装を基本にしてよい。

### 使用範囲のパターン
14サイト中、和菓子店（nasu-ougiya.com、8割が縦組、本人コメント）や shirahone.org（メニュー含め全面的に使用）のようにサイト全体を縦組で統一する例もあるが、より多数派（meikei.ac.jp「ヒーローエリアのみ」、kajimanomori.co.jp「利用箇所は少ないがポイントで使用」など）は、ヒーローの短いコピーや1〜2箇所のアクセントとして縦組を使い、他は横組のままにする「部分使用」パターンだった。実装コストと可読性への影響を抑えつつ縦組の効果を得たい場合は、この部分使用パターンを基本形として推奨する。

### 実務での判断基準
1. **短い日本語コピー（1〜2行程度の見出し・キャッチコピー）がある箇所では、横組にする前に縦組の可能性を検討する。** 特にヒーローエリアの主要コピーは縦組との相性が良い。
2. 長文の本文・説明文・フォーム等、可読性とスクロール挙動が重要な箇所は横組を維持する。縦組は禁物ではないが、実例でも本文全体を縦組にしている例は少数派である。
3. 業種のトーンが和風・伝統寄り（神社、和菓子、旅館、着物、書道、冠婚葬祭等）であれば、明朝体×広め字間・行間の「パターンA」を基本形にする。
4. 業種のトーンが力強さ・誠実さ・親しみやすさを狙う場合（採用、教育機関の訴求、EC）は、ゴシック体×タイトな行間・weight 600〜700 の「パターンB」を検討する。
5. 実装は基本的に `writing-mode: vertical-rl;` とする。英数字を横向きのまま縦組に混植したい場合は `text-orientation: mixed;` も合わせて検討する。全面縦組ではなく、見出し・キャッチコピーなど範囲を絞った部分使用を基本形とする。
6. 具体的な数値（font-size・letter-spacing・line-height・font-weight）を決める際は `data/vertical_writing_examples.csv` の該当パターンの実測値を出発点にする。

## 3. 「AIっぽさ」を避けるための判断原則

データが無い状態でAIにデザインを作らせると、学習データの中で最も"それっぽい"平均的なパターンに収束しやすい。これを避けるための考え方。

- **抽象語をそのまま使わない**：「おしゃれに」「かっこよく」のような指示をそのまま解釈せず、`data/`のCSVで該当業種の実測値（色・フォント・トーン％）に変換してから判断する。
- **一つの正解に逃げない**：同じ業種でも「モデレート（堅実・上品）」と「ボールド（大胆・実験的）」の2つの参照点を必ず意識する。詳細は下記「3. moderate / bold ダイアル」を参照。
- **具体例を経由する**：`data/css_reference_examples.csv` には実在サイトの実測hexコード・font-family・ボタンの角丸値が入っている。抽象的な色名（「上品な青」等）で止めず、可能な限り具体的な数値（`#0A0801` のようなダークトーン、`border-radius: 9999px` の完全な丸ボタン等）まで踏み込む。
- **業種の"らしさ"と"無難さ"は別物**：業種平均に忠実であることと、無難でつまらないデザインになることは紙一重。平均値は「外してはいけない一線」を知るために使い、実際の意匠は具体例（実測18サイト・38サイトの質的事例）から発想を借りる。

### 陥りやすい"AI丸わかり"パターン

データに基づかずに生成すると、以下のような定番パターンに収束しやすい。ブリーフが明示的に求めている場合を除き、避ける。

- 生成りベージュ（`#F4F1EA`系）の背景＋高コントラストなセリフ見出し＋テラコッタ/レンガ色（`#D97757`系）のアクセント
- ほぼ黒の背景＋単色の蛍光グリーンや朱色だけのアクセント
- 罫線だけの新聞的レイアウト（border-radius: 0、余白の詰まった段組）
- 同じ角丸・同じ薄灰色シャドウ（`rgba(0,0,0,.1)`系）・グラデーション装飾の量産型カード
- 英字ラベルの多用：字間を広げたALL CAPSの"eyebrow"、中黒（・）区切りのメタ情報、'WORD — fragment'調のラベル、モノスペースのデータ表示、リンク末尾に'→'を機械的に付ける
- セクション見出しに `text-wrap:balance` や角丸カードなど、"それらしい"実装だけを機械的に踏襲し、業種の実測データ（`data/`のCSV）と照合しないこと

判断のコツ：見出し・配色・カード装飾のどれか一つが上記に当てはまっただけで即NGにする必要はないが、**複数が同時に揃っている場合は要警戒**。`data/css_reference_examples.csv`等の実測例と照らして、本当にその業種で使われている意匠かどうかを確認する。

### 一般的なデザイン原則・最終レビューの手順

近接・整列・強弱・反復といった一般的なレイアウト原則、配色の比率、タイポグラフィの基本（フォント数・行長の目安）、モーションの節度、UIライティングの原則、そして「計画→レビュー→実装→批評」という4段階の進め方は、業種を問わない普遍的な設計原則として `references/general-design-principles.md` にまとめている。特に新規にページ全体をレイアウトするときや、実装後の最終レビュー（`SKILL.md` ステップ7）ではこのファイルも参照すること。

## 4. moderate / bold ダイアル

今回のデータ基盤には、同じ業種について2つの参照点がある。

- **moderate（choooodoii由来）**：着実に実装された、バランスの取れた良質サイトの母集団統計。「堅実」「外さない」方向の基準線。
- **bold（81-web由来）**：大胆なレイアウト・実験的な表現に振ったサイトの統計。「攻めた」「印象に残る」方向の基準線。

ユーザーのブリーフに「保守的に」「王道で」といった指定があればmoderate寄り、「印象的に」「他社と差別化したい」「攻めたデザインで」といった指定があればbold寄りに解釈する。指定がなければ、業種の性質（例: 金融・医療は基本moderate寄り、アート・エンタメはbold寄りを許容しやすい）と、moderateとboldの実測値の差が大きい項目（例: IT・システムの動きtag保有率はmoderateの想定より高く出る）を手がかりに、Claude自身が妥当な位置を判断してよい。

現時点でbold（81-web）側のデータがあるのは以下の6業種のみ（`data/boldness_moderate_vs_bold.csv`）。それ以外の業種はmoderate（choooodoii）側の統計のみを基準にすること。データがない業種でboldな指定をされた場合は、無理に数値を捏造せず、近い性質を持つ業種のboldデータを参考にする旨を明示した上で判断する。

- 不動産・建築・空間・施設
- ウェディング
- 暮らし商品・サービス
- アート
- 美容
- IT・システム

## 5. データの出典と扱い

`data/`以下のCSVは、choooodoii.com（バランス型ギャラリー）と81-web.com（実験型ギャラリー）という2つの日本語Webデザインギャラリーサイトの、業種・タイプ・色・フォント等の分類ラベルおよびその集計値をもとに作成している。両サイトのサムネイル画像やキュレーターの紹介文をそのまま複製したものではない。詳しい取得方法・出典についてはリポジトリの `README.md` を参照。
